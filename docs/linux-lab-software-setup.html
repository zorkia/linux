1. เตรียม Container และผู้ใช้

บน Windows ใช้ PowerShell หรือ Windows Terminal ส่วน macOS ใช้ Terminal เปิด Container ที่สร้างไว้ใน LAB 01:

docker start -ai rpi-lab

ถ้า Container กำลังทำงานอยู่ ให้เปิด Terminal เพิ่มด้วย:

docker exec -it rpi-lab bash

ใน Container ใหม่ที่ยังไม่มี sudo ให้รันด้วยผู้ใช้ root ตาม LAB 01:

apt update
apt install -y sudo adduser

สร้าง piuser และเพิ่มเข้า Group sudo ตาม LAB 01 ก่อนทำขั้นตอนถัดไป ถ้ามีผู้ใช้นี้อยู่แล้ว ให้ใช้งานต่อได้เลย

2. ติดตั้งแพ็กเกจ APT ล่วงหน้า

รันภายใน Container หลังเปลี่ยนเป็น piuser:

su - piuser
sudo apt update
sudo apt install -y sudo adduser nano less tree file curl ca-certificates procps htop iproute2 iputils-ping dnsutils netcat-openbsd python3 python3-pip python3-venv nginx sqlite3 mosquitto mosquitto-clients nodejs npm

คำสั่งนี้ติดตั้งเครื่องมือสำหรับทั้งชุด LAB ถ้าแพ็กเกจติดตั้งอยู่แล้ว APT จะตรวจสอบเวอร์ชันและติดตั้งหรืออัปเกรดเฉพาะที่จำเป็น ใช้ Container เดิมต่อไปเพื่อเก็บโปรแกรมและข้อมูลจากแล็บก่อนหน้า

3. เตรียม Python Virtual Environment

ใช้โฟลเดอร์และชื่อ venv เดียวกับ LAB 10, 15 และ 16 รันด้วย piuser:

mkdir -p ~/python-lab
python3 -m venv ~/python-lab/venv
source ~/python-lab/venv/bin/activate
python -m pip install requests paho-mqtt
python -c "import requests; import paho.mqtt.client; print('Python packages OK')"
deactivate

ก่อนใช้ไลบรารีเหล่านี้ในแต่ละ Terminal ให้เปิด venv อีกครั้งด้วย source ~/python-lab/venv/bin/activate การติดตั้งด้วย pip ใน venv นี้จะไม่ทำให้ไลบรารีพร้อมใช้ใน venv อื่น

โมดูล sqlite3, json, random, time, pathlib และ http.server เป็นส่วนหนึ่งของ Python ที่ใช้ในชุด LAB นี้ ไม่ต้องติดตั้งเพิ่มด้วย pip

4. ติดตั้ง Node-RED

หลังติดตั้ง nodejs และ npm แล้ว รันภายใน Container:

sudo npm install -g --unsafe-perm node-red
node --version
npm --version
node-red --version

การติดตั้งล่วงหน้าเตรียมเฉพาะโปรแกรม ส่วนไฟล์ตั้งค่า Listener, Nginx Proxy, โค้ด Python, ฐานข้อมูล และ Flow ให้สร้างตามแต่ละ LAB บริการที่ติดตั้งอาจเริ่มทำงานระหว่างติดตั้ง แต่เมื่อหยุดและเปิด Container ใหม่ต้องตรวจและเริ่มบริการตามขั้นตอนใน LAB

5. ตรวจว่าคำสั่งพร้อมใช้

รันด้วย piuser ภายใน Container:

for cmd in sudo adduser nano less tree file curl ps top pgrep pkill free uptime htop ip ss ping dig nc python3 pip3 nginx sqlite3 mosquitto mosquitto_pub mosquitto_sub node npm node-red; do
    if command -v "$cmd" >/dev/null 2>&1; then
        echo "OK: $cmd"
    elif sudo sh -c 'command -v "$1" >/dev/null 2>&1' sh "$cmd"; then
        echo "OK (sudo PATH): $cmd"
    else
        echo "MISSING: $cmd"
    fi
done

คำสั่งใน /usr/sbin เช่น nginx หรือ adduser อาจไม่อยู่ใน PATH ของ piuser แม้ติดตั้งแล้ว จึงตรวจผ่าน sudo ด้วย ตัวอย่างตรวจเวอร์ชัน Nginx ให้ใช้ sudo nginx -v ตาม LAB 11

ถ้าขึ้น MISSING ให้ดูชื่อแพ็กเกจจากตารางด้านบน ส่วน python และ pip ที่ใช้ใน LAB Python ต้องตรวจหลังเปิด venv แล้ว

เครื่องมือที่ใช้เฉพาะฝึกติดตั้งและถอนโปรแกรม

cowsay ใน LAB 04 ใช้ฝึกติดตั้ง ตรวจสอบ และถอนแพ็กเกจ จึงติดตั้งเมื่อถึงแบบฝึกหัดนั้น:

sudo apt install -y cowsay

จากนั้นทำขั้นตอนถอนด้วย sudo apt remove -y cowsay ตาม LAB 04 ไม่จำเป็นต้องเก็บไว้สำหรับแล็บถัดไป

คำสั่งพื้นฐานที่มีอยู่ใน Image

คำสั่งอย่าง ls, cp, mv, rm, cat, head, tail, sort, cut, wc, tee, df, du, nohup, grep, find, hostname, getent, which, su, usermod และ groupadd มาจากแพ็กเกจพื้นฐานของ Debian Image ที่ใช้ใน LAB จึงไม่ได้รวมเป็นเครื่องมือที่ต้องติดตั้งเพิ่ม ส่วน cd, export, source, alias, jobs, fg, bg, wait, trap, printf, history และ kill ที่ใช้ใน Bash เป็นคำสั่งภายใน Shell

พื้นฐาน Background Process และ nohup อยู่ใน LAB 05 ตัวอย่าง Bash Script อยู่ใน LAB 09 และ Python Script อยู่ใน LAB 10 ไม่ต้องติดตั้งเครื่องมือ Background เพิ่มนอกเหนือจาก procps สำหรับตรวจ Process

ตัวอย่างที่เคยขาดใน Image แบบย่อคือ ps, top และ free ต้องติดตั้ง procps แม้จะเป็นคำสั่งที่พบได้ทั่วไปบน Linux เครื่องเต็ม รายการคำสั่งในแพ็กเกจตรวจสอบได้จาก Debian: procps และ Debian: debianutils
