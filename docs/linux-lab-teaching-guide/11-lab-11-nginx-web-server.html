วัตถุประสงค์

ติดตั้งและใช้งาน Nginx ภายใน Debian Container เพื่อเข้าใจ Web Server บน Raspberry Pi

LAB 01 ควรสร้าง Container rpi-lab พร้อม -p 8080:80 แล้ว เพื่อให้ Browser บน Windows/macOS เปิด Nginx ใน Container ได้ผ่าน http://localhost:8080

ถ้าใช้ Container เก่าที่ไม่ได้กำหนด -p 8080:80 จะทดสอบได้เฉพาะภายใน Container ด้วย curl http://127.0.0.1 เท่านั้น และไม่สามารถเพิ่ม Port Mapping ให้ Container เดิมโดยตรงได้ ต้องสำรองข้อมูลแล้วสร้าง Container ใหม่ให้ถูกต้อง

เริ่มต้น

docker start -ai rpi-lab
su - piuser
sudo apt update
sudo apt install -y nginx curl procps iproute2
sudo nginx -v
nginx อยู่ใน /usr/sbin/nginx ซึ่ง user ธรรมดาอาจไม่มี /usr/sbin อยู่ใน PATH จึงใช้ sudo nginx -v เพื่อตรวจ version
procps มีคำสั่ง ps และ pgrep ส่วน iproute2 มีคำสั่ง ss สำหรับตรวจ process และ port ที่ใช้งานอยู่

เริ่ม Nginx

Docker Container นี้ไม่ได้ boot ด้วย systemd แบบ Raspberry Pi จริง:

pgrep nginx || sudo nginx
ps aux | grep '[n]ginx'
ss -tuln | grep :80

ถ้ารัน sudo nginx แล้วขึ้นข้อความ bind() to 0.0.0.0:80 failed (98: Address already in use) แปลว่า port 80 มี process ใช้งานอยู่แล้ว โดยส่วนใหญ่คือ Nginx รันอยู่แล้ว ให้ตรวจด้วย ps และ ss แล้วไปขั้นตอนทดสอบได้เลย

ทดสอบ

ทดสอบจากภายใน Container:

curl http://127.0.0.1

ทดสอบจาก Browser บน Windows/macOS:

http://localhost:8080

ถ้าเครื่องอื่นอยู่ใน LAN เดียวกัน ให้ใช้ IP ของ Windows/macOS host:

http://IP-WINDOWS:8080

ถ้าเปิดจากเครื่องอื่นไม่ได้ ให้ตรวจสอบ Windows Firewall หรือ Firewall ของเครื่อง host ว่าอนุญาต port 8080 แล้วหรือยัง

Web Root

ls -la /var/www/html
sudo nano /var/www/html/index.html

ใส่:

<!DOCTYPE html>
<html>
<head><meta charset="UTF-8"><title>IoT Lab</title></head>
<body>
<h1>Raspberry Pi IoT Lab</h1>
<p>Nginx is running.</p>
</body>
</html>

ทดสอบ:

curl http://127.0.0.1

จาก Browser บน Windows/macOS ให้ Refresh หน้า:

http://localhost:8080

Configuration

ls /etc/nginx
ls /etc/nginx/sites-enabled
sudo nginx -t
sudo nginx -s reload

Nginx กับ Web Application

ใน LAB 12 จะใช้ Nginx เป็นหน้าเว็บหลักสำหรับระบบ IoT Device Status Log โดยให้ Nginx ทำ 2 หน้าที่:

Browser
  |
  | http://localhost:8080/status.html
  v
Nginx
  |-- Static page: /var/www/html/status.html
  |
  |-- Proxy /api/ ไปยัง Python API ที่ 127.0.0.1:5000

แนวคิดนี้ใกล้กับงานจริงบน Raspberry Pi เพราะ Nginx ทำหน้าที่เป็น Web Server ด้านหน้า ส่วน Python ทำหน้าที่รับข้อมูลและคุยกับ SQLite

ทำไมต้องใช้ Nginx Proxy

ถ้าเปิด Python API ตรง ๆ ผู้ใช้ต้องจำ URL และ port แยก เช่น http://localhost:5000/api/logs ในขณะที่หน้าเว็บอยู่ที่ http://localhost:8080/status.html ทำให้ระบบดูแยกเป็นสองส่วน

การตั้งค่า Nginx Proxy ทำให้ Browser เรียกทุกอย่างผ่าน Web Server ตัวเดียว:

หน้าเว็บ        http://localhost:8080/status.html
API            http://localhost:8080/api/logs

Nginx จะรับ request ที่ขึ้นต้นด้วย /api/ แล้วส่งต่อไปยัง Python API ภายใน Container:

Browser
  |
  | /api/logs
  v
Nginx :80
  |
  | proxy_pass
  v
Python API :5000
  |
  v
SQLite

ประโยชน์คือ Browser เห็นระบบเป็นเว็บเดียวกัน, ซ่อน port ของ Python API ไว้ด้านหลัง Nginx, และต่อยอดไปใช้ HTTPS หรือ domain จริงบน Raspberry Pi ได้ง่ายกว่า

หยุด:

sudo nginx -s stop

เริ่มใหม่:

pgrep nginx || sudo nginx

Docker กับ Pi จริง

บน Raspberry Pi ที่ boot ด้วย systemd มักใช้ systemctl แต่ใน Container ชุดนี้ไม่ใช้ systemctl เป็นแกนหลัก

บน Raspberry Pi จริง Browser จะเรียก IP ของ Raspberry Pi โดยตรง เช่น http://192.168.1.20 แต่ใน Docker ต้องเข้าผ่าน Windows/macOS host port เช่น http://localhost:8080

แบบฝึกหัด

สร้าง /var/www/html/iot.html แสดง Student ID, Hostname และข้อความ IoT Gateway แล้วทดสอบ:

curl http://127.0.0.1/iot.html

จาก Browser บน Windows/macOS:

http://localhost:8080/iot.html
