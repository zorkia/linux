ก่อนหน้า: LAB 05 - Linux Processes และ Resource Monitoringกลับหน้าแรกถัดไป: LAB 07 - Linux Pipes, Redirects และ Text Processing
เครื่องมือสำหรับ LAB นี้

ใช้ ip, ss จาก iproute2, ping จาก iputils-ping, dig จาก dnsutils, nc จาก netcat-openbsd และ curl พร้อม ca-certificates สำหรับ HTTPS ดู รวมคำสั่งและการติดตั้งล่วงหน้า

วัตถุประสงค์

เข้าใจ Interface, IP Address, Route, DNS, Port และการทดสอบ Network ภายใน Docker โดยเชื่อมโยงกับ Raspberry Pi

ใน Docker ต้องแยกให้ชัดว่า IP ภายใน Container ไม่ใช่ IP ของ Windows/macOS host และไม่ใช่ IP ของ Raspberry Pi จริง การเปิดบริการให้ Browser หรือเครื่องอื่นใน LAN เข้าใช้งานต้องอาศัย Docker Port Mapping ที่กำหนดตอนสร้าง Container

เริ่มต้น

docker start -ai rpi-lab
su - piuser

ติดตั้งเครื่องมือ:

sudo apt update
sudo apt install -y iproute2 iputils-ping curl ca-certificates dnsutils netcat-openbsd

1. Hostname

hostname

2. Interface/IP

ip addr

หา eth0 และ IP เช่น:

inet 172.17.0.x/16

3. Route

ip route

หา Default Gateway:

default via 172.17.0.1 dev eth0

4. Internet

ping -c 4 8.8.8.8

5. DNS

ping -c 4 google.com
cat /etc/resolv.conf

ใช้ DNS query:

dig google.com

6. HTTP

curl -I https://example.com

7. Port และ Socket

ss -tuln

ความหมายหลัก:

-t TCP
-u UDP
-l Listening
-n แสดงหมายเลข Port

8. เปิด TCP Server ทดลอง

Terminal ภายใน Container:

nc -l -p 9000

เปิด Terminal Windows อีกหน้าต่าง:

docker exec -it rpi-lab bash

แล้ว:

su - piuser
nc 127.0.0.1 9000

พิมพ์ข้อความทดสอบระหว่าง Client/Server

9. Docker Network กับ Raspberry Pi

Docker:
Container eth0 → Docker Bridge → Windows → Network

Raspberry Pi:
Pi eth0/wlan0 → Router/AP → Network
Docker Lab ไม่มี wlan0 จริง และไม่ควรใช้ LAB นี้แทนการสอน Wi-Fi hardware/configuration บน Pi

แบบฝึกหัด

เก็บผล:

hostname
ip addr
ip route
cat /etc/resolv.conf
dig google.com
ss -tuln
curl -I https://example.com

คำถามท้าย LAB

  1. IP Address, Gateway และ DNS มีหน้าที่อะไร
  2. ip addr กับ ip route ต่างกันอย่างไร
  3. Port คืออะไร
  4. Docker eth0 เหมือน/ต่างจาก Raspberry Pi อย่างไร
