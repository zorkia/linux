วัตถุประสงค์

เขียน Shell Script เพื่อทำงาน Linux แบบอัตโนมัติ และเตรียมแนวคิดสำหรับงานดูแล Raspberry Pi/IoT Gateway

nano hello.sh

ใส่:

chmod +x hello.sh
./hello.sh

10. Bash Script แบบ Background

ตัวอย่างงานจริง: เก็บเวลา ชื่อเครื่อง และพื้นที่ดิสก์ของ Gateway ทุก 5 วินาทีลง log โดยยังใช้ Terminal ทำงานอื่นได้

ทบทวน &, nohup, $! และ signal ใน LAB 05 - Background Job ก่อนเริ่ม

สร้างไฟล์:

mkdir -p ~/scripts ~/logs
nano ~/scripts/gateway-monitor.sh

ใส่:

#!/bin/bash

trap 'echo "Monitor stopped"; exit 0' TERM

while true
do
    printf '%s host=%s\n' "$(date '+%Y-%m-%dT%H:%M:%S%z')" "$(hostname)"
    df -h / | tail -n 1
    sleep 5
done

trap ให้สคริปต์จบอย่างเป็นระเบียบเมื่อได้รับ SIGTERM ถ้ากำลังรอ sleep อาจใช้เวลาไม่เกินประมาณ 5 วินาทีก่อนจบ

10.1 เริ่มและเก็บ PID

รันเพียงครั้งเดียว ไม่ต้องรันซ้ำทุกครั้งที่ต้องการดู log:

nohup bash "$HOME/scripts/gateway-monitor.sh" >> ~/logs/gateway-monitor.log 2>&1 < /dev/null &
monitor_pid=$!
printf '%s\n' "$monitor_pid" > ~/logs/gateway-monitor.pid
ps -p "$monitor_pid" -o pid,user,stat,args

ใช้ bash เรียกไฟล์โดยตรง จึงไม่จำเป็นต้อง chmod +x ในตัวอย่างนี้ >> เก็บ log ต่อจากเดิม และไฟล์ .pid ช่วยจำ PID เมื่อต้องตรวจจาก Terminal อีกหน้าต่าง

10.2 ดู Log

tail -n 20 ~/logs/gateway-monitor.log
tail -f ~/logs/gateway-monitor.log

tail -f แสดงบรรทัดใหม่ต่อเนื่อง กด Ctrl+C เพื่อหยุดดู log เท่านั้น ตัว gateway-monitor.sh ยังทำงานอยู่

ตัวอย่างผลลัพธ์ (เวลา ชื่อเครื่อง และค่าดิสก์จะแตกต่างกัน):

2026-10-07T10:00:00+0700 host=raspberrypi
overlay  100G  20G  80G  20% /

10.3 หยุดเฉพาะสคริปต์นี้

อ่าน PID แล้วตรวจชื่อคำสั่งก่อน:

monitor_pid=$(cat ~/logs/gateway-monitor.pid)
ps -p "$monitor_pid" -o pid,user,stat,args

ต้องเห็น bash /home/piuser/scripts/gateway-monitor.sh จึงหยุดด้วย:

kill "$monitor_pid"

รอประมาณ 5 วินาทีแล้วตรวจ:

ps -p "$monitor_pid" -o pid,user,stat,args
tail -n 5 ~/logs/gateway-monitor.log

ไม่ควรพบสคริปต์เดิมใน ps และ log ควรมี Monitor stopped จากนั้นลบไฟล์ PID ที่ไม่ใช้งานแล้ว:

rm -f ~/logs/gateway-monitor.pid
ไฟล์ PID ไม่ใช่หลักฐานว่าโปรแกรมยังทำงานอยู่ ถ้าโปรแกรมจบหรือ Container restart เลข PID อาจถูกใช้โดยโปรแกรมอื่น ต้องตรวจชื่อ Process ก่อน kill ทุกครั้ง ถ้าไม่ตรง ห้ามใช้ PID นั้น และไม่ควรใช้ pkill bash เพราะจะกระทบ Shell อื่น
สคริปต์นี้เก็บค่าดิสก์ที่ Container มองเห็น ไม่ใช่ดิสก์ของ Raspberry Pi จริงโดยตรง และ log จะโตต่อเนื่อง งานใช้งานระยะยาวต้องจัดการขนาด/หมุนเวียน log และใช้ตัวจัดการ service ตามสภาพแวดล้อม ส่วน nohup ใช้ฝึกการเริ่มและดูแล Process ในแล็บนี้
