4. Background Job

Foreground คือโปรแกรมที่กำลังครอง Terminal เช่น top ส่วน Background คือโปรแกรมที่ทำงานไปพร้อมกับการที่เราใช้ Shell พิมพ์คำสั่งอื่นได้

เครื่องหมาย & ท้ายคำสั่งทำให้ Shell เริ่มงานแบบ Background แต่ไม่ได้ทำให้โปรแกรมเร็วขึ้น และไม่ได้รับประกันว่าจะทำงานต่อเมื่อปิด Terminal

jobs -l

jobs -l แสดง Job ID และ PID ของงานใน Shell นี้ Job ID เช่น [1] ไม่ใช่ PID ของ Process และ Terminal อีกหน้าต่างจะมีรายการ jobs ของตัวเอง

4.1 สลับ Foreground / Background

สร้างงานใหม่:

sleep 500 &
jobs -l

นำงานปัจจุบันกลับมา Foreground (%+ หมายถึง current job ที่ Bash ทำเครื่องหมาย + ในรายการ jobs):

fg %+

ตอนนี้ Shell จะรอ sleep กด Ctrl+Z เพื่อพักงาน แล้วตรวจ:

jobs -l

งานจะเป็น Stopped ซึ่งยังไม่ถูกปิด ให้ทำงานต่อใน Background:

bg %+
jobs -l

นำกลับมา Foreground แล้วกด Ctrl+C เพื่อหยุดงานทดลองนี้:

fg %+

fg / bg ใช้กับงานใน interactive Bash เดียวกัน ถ้าจะเลือกงานอื่น ให้ใช้ Job ID เช่น fg %1 โดยดูเลขจาก jobs ก่อน

4.2 เก็บ PID ด้วย $!

$! คือ PID ของงาน Background ที่เพิ่งเริ่มล่าสุด ต้องเก็บค่าทันที ก่อนเริ่มงานอื่น:

sleep 300 &
sleep_pid=$!
echo "$sleep_pid"
ps -p "$sleep_pid" -o pid,user,stat,args

หยุดเฉพาะ Process ที่เก็บ PID ไว้ แล้วรอให้จบ:

kill "$sleep_pid"
wait "$sleep_pid"
echo $?

kill แบบไม่ระบุ signal ส่ง SIGTERM เพื่อขอให้โปรแกรมจบ ส่วน wait รอ child process ของ Shell นี้และคืน exit status ในตัวอย่าง sleep ที่ถูก SIGTERM ค่าปกติใน Bash คือ 143 ไม่ใช่ความผิดพลาดของคำสั่ง kill

ถ้าเปิด Shell ใหม่ จะใช้ ps / kill กับ PID ได้ แต่ใช้ wait กับ Process ที่ไม่ได้เริ่มจาก Shell นั้นไม่ได้

12. nohup และการปิด Terminal

nohup ให้โปรแกรมไม่หยุดเพราะ signal SIGHUP ที่เกี่ยวกับการปิด session แต่ต้องใส่ & เองจึงจะรันแบบ Background

ทดลองรันและเก็บ PID:

nohup sleep 300 > ~/sleep.log 2>&1 < /dev/null &
sleep_pid=$!
ps -p "$sleep_pid" -o pid,user,stat,args
ส่วนของคำสั่ง หน้าที่
nohup ให้โปรแกรม ignore SIGHUP
> ~/sleep.log เขียน stdout ลงไฟล์ โดยแทนที่เนื้อหาเดิม
>> ~/sleep.log ใช้แทน > เมื่อต้องการเพิ่ม log ต่อท้าย
2>&1 ให้ stderr ไปที่เดียวกับ stdout ต้องวางหลังการ redirect stdout
< /dev/null ไม่อ่าน input จาก Terminal
& เริ่มงาน Background
$! PID ของงานที่เพิ่งเริ่ม

sleep ไม่พิมพ์ข้อมูลตามปกติ ดังนั้น sleep.log อาจว่าง ดูตัวอย่างที่มี log ใช้งานจริงใน LAB 09 - Bash Background และ LAB 10 - Python Background

จบการทดลองนี้ด้วย:

kill "$sleep_pid"
wait "$sleep_pid"

ข้อจำกัดเมื่อใช้ Docker

nohup ไม่ใช่ตัวจัดการ service: ไม่ restart โปรแกรมเมื่อ crash ไม่เริ่มงานใหม่หลัง reboot และไม่ทำให้ Process อยู่ต่อเมื่อ Container หยุด

ใน Container นี้ Bash หลักเป็น PID 1 ถ้า exit จน Bash หลักจบ Container จะหยุดและ Background Process ทั้งหมดจบด้วย

ถ้า attach ผ่าน docker start -ai rpi-lab ให้กด Ctrl+P แล้ว Ctrl+Q เพื่อ detach โดยไม่หยุด Container ส่วน exit จาก Shell ที่เปิดด้วย docker exec จะปิดเฉพาะ session นั้น

วิธีฝึกปิด session โดยไม่แตะ Bash หลัก: เปิด Terminal บน Windows/macOS อีกหน้าต่าง แล้วเข้า Shell ใหม่:

docker exec -it -u piuser rpi-lab bash

คำสั่ง Background ในแล็บนี้ต้องรันภายใน Bash ของ Container ไม่ใช่ PowerShell เมื่อหยุดแล้ว start Container ใหม่ ต้องเริ่มสคริปต์ใหม่เอง แม้ไฟล์สคริปต์และ log ใน Container เดิมยังอยู่
